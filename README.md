# 교실 화면 공유 v1

크롬북 학생의 화면을 교사 PC에서 실시간으로 확인하는 **무료 WebRTC 직접 연결 실험용** 웹앱입니다.

**현재 상태:** 초기 소스 업로드 완료. Firebase 규칙 게시, 교사 관리자 UID 등록, GitHub Pages 설정 및 실제 연결 시험은 아직 완료되지 않았습니다. 실수업 사용 전 안전성과 안정성 검증이 필요합니다.

## v1 기능
- 이메일/비밀번호 교사 로그인, 교사 관리자 UID 확인
- 7자리 교실 코드 생성 및 학생용 링크 복사
- 학생 익명 인증 + 화면 공유 동의
- 학생 영상 25분할 / 4분할 / 1명 확대
- 학생 공유 중 안내, 학생 공유 중지, 교사 전체 종료
- WebRTC 직접 연결 여부에 대한 기본 진단
- 화면 녹화·서버 영상 저장 없음

**아직 없는 기능:** 랜덤 발표, 자동 넘김, 링크 전송, 교사 화면 송출, 안정적인 자동 재연결.

## 무료 운영의 전제
- GitHub Pages와 Firebase **Spark 무료 요금제** 이용
- 영상은 Firebase로 보내지 않고 WebRTC로 직접 전송
- 무료 STUN만 사용. TURN 중계 서버가 **없으므로 직접 연결이 차단된 학교 환경에서는 작동하지 않을 수 있음**
- 무료 정책이나 사용량 제한에 따라 서비스가 중단될 수 있음. 영구 무료 가동 보장은 아님
- 결제 계정 연결 또는 Blaze 업그레이드를 하지 않음

## 1. Firebase 교사 관리자 UID 등록
1. Firebase 콘솔 → Authentication → 사용자
2. 교사 이메일/비밀번호 계정의 **전체 사용자 UID** 복사
3. Realtime Database → 데이터 탭
4. 루트에 admins 노드를 만들고, 그 아래 **전체 UID를 키로 사용하는 Boolean 값 true**를 저장

예시 (아래는 실제 UID가 아닙니다):

    admins
      EXAMPLE_TEACHER_UID: true

이 작업은 Firebase 콘솔에서 프로젝트 소유자가 수행합니다. 학생에게 이 권한을 주지 않습니다.

## 2. Firebase 데이터베이스 보안 규칙 게시
1. Realtime Database → **규칙** 탭
2. 이 저장소의 [database.rules.json](./database.rules.json) **전체 내용**을 붙여넣음
3. **게시** 버튼 클릭
4. Firebase 규칙 시뮬레이터를 이용해 학생의 관리자 쓰기가 차단되는지 검사

중요: **GitHub에 규칙 파일을 업로드했다고 Firebase에 자동 적용되는 것은 아닙니다.** 초기 잠금 규칙을 무턱대고 공개 규칙으로 변경하지 마세요.

## 3. Firebase 승인된 도메인
Authentication → 설정 → 승인된 도메인에 **slowjjb.github.io** 등록.

기존에 등록한 slowjib.github.io는 오타입니다. 삭제해도 됩니다.

## 4. GitHub Pages 사용 설정
저장소 → Settings → Pages → Build and deployment

- Source: Deploy from a branch
- Branch: main
- Folder: /(root)
- Save

예상 접속 주소: https://slowjjb.github.io/classroom-screen-share/

## 5. 테스트 순서
1. 교사 PC에서 웹앱을 열고 Firebase 교사 이메일/비밀번호로 로그인
2. '새 교실'을 눌러 7자리 코드를 생성
3. '학생 주소 복사'를 눌러 크롬북으로 열기
4. 학생은 코드·시험용 이름 입력 후 '화면 선택하고 공유 시작'
5. Chrome 공유 선택창에서 공유할 화면 승인
6. 교사 PC에서 25/4/1분할 확인
7. 학생의 공유 중지 및 교사 전체 종료 시험
8. 2명 → 4명 → 10명 → 20명으로 확대 시험

**실제 학생 정보 대신 시험용 별명을 먼저 사용하세요.** Chrome은 매번 학생이 직접 화면 공유를 허용해야 하며, 몰래 화면을 수집하지 않습니다.

## 6. 파일
- index.html: 교사·학생 UI, Firebase 인증, WebRTC 연결
- database.rules.json: 교사/학생 데이터베이스 권한 분리
- README.md: 설정 절차와 테스트 계획

## 7. 오류 대응
- 교사 권한 없음: admins/교사UID = true 여부 확인
- permission_denied: 규칙 게시 여부 및 UID 확인
- 공유 중 영상 연결 실패: 학교 방화벽, STUN, 크롬북 정책 확인; TURN은 미구현
- 공유 버튼 작동 안 함: HTTPS와 최신 Chrome 및 화면 공유 권한 확인

**주의:** 초기 v1 소스는 실제 기기 및 보안 테스트를 거치지 않은 개발 초안입니다. 작동이 확인되기 전에는 정규 수업에 사용하지 마세요.

## v1.1 · 프레임률 개선 (2026-11-26)
- v1 화면 공유에서 코드로 최대 4fps로 제한하던 설정을 수정했습니다.
- 학생 화면에 전송 프레임률 선택 메뉴를 추가했습니다: 절약(4fps) / 표준(12fps·기본값) / 부드럽게(18fps·소규모 시험용).
- 변경은 **학생이 화면 공유를 시작할 때** 적용됩니다. 공유 중에는 변경할 수 없으므로 공유를 중지한 뒤 다시 시작해야 합니다.
- 실제 fps는 Chromebook·브라우저·콘텐츠 변경량·네트워크 환경에 따라 달라지며 표시된 값에 미달할 수 있습니다.
- 무료 WebRTC 직접 전송 원칙과 Firebase 데이터 구조/보안 규칙은 변경하지 않았습니다.
- 우선 교사 1명 + 크롬북 1~4대에서 표준/부드럽게 옵션을 비교한 뒤 20명 환경에서 부하를 시험하세요.

## v1.2 · 교사 화면 모드에 따른 자동 FPS (2026-11-26)
- 학생 화면의 품질 선택 기본값이 **자동**으로 바뀌었습니다.
- **25분할:** 전 학생 최대 8fps 목표
- **4분할:** 화면에 표시된 네 명은 최대 12fps, 표시되지 않은 학생은 최대 8fps 목표
- **1명 확대:** 선택된 한 명은 최대 18fps, 나머지 학생은 최대 8fps 목표
- 학생 크롬북으로 보내는 품질 제어 명령은 **기존 WebRTC DataChannel**을 사용합니다. Firebase 신호 데이터베이스 규칙은 바뀌지 않았습니다.
- 학생은 수동 절약 4fps / 표준 12fps / 부드럽게 18fps를 선택할 수도 있습니다. 수동 모드에서는 교사 화면에 따른 변경을 무시합니다.
- 캡처 트랙의 `applyConstraints`와 송신기 `setParameters`를 시도합니다. 브라우저·기기·네트워크 특성에 따라 실제 수신 FPS와 일치하지 않을 수 있습니다.
- 연결 중인 교사·학생 모두 **새로고침하고 새 교실로 다시 연결**해야 이 버전의 자동 제어 기능이 정상적으로 적용됩니다.
- 영상은 계속 WebRTC 직접 전송을 우선 사용하고, TURN 중계는 추가하지 않았습니다.

## v1.3 · 실시간 WebRTC 수신 진단 (2026-11-26)

교사 화면에 학생별 수신 품질과 학급 전체 트래픽을 볼 수 있는 진단을 추가했습니다.

- **학생 타일:** 디코딩된 실제 수신 프레임률(fps), 실제 수신 영상 비트레이트(Mbps), 연결 경로
- **상단 합계:** 측정 가능한 연결 수, 연결된 학생의 평균 수신 fps, 합계 Mbps, 현재 연결들의 누적 수신량(MB), 직접 연결/중계 연결 수
- **갱신 주기:** 3초. 각 학생별 `RTCPeerConnection.getStats()` 결과를 교사 브라우저에서 계산합니다.
- **비교할 목표:** 자동 25분할 최대 8fps, 4분할 표시 대상 12fps, 1명 확대 18fps. 실제 측정 fps와 목표 fps는 다를 수 있습니다.
- 화면에 변화가 거의 없으면 실제 디코딩 FPS가 낮게 표시될 수 있으며, 반드시 성능 저하를 의미하지는 않습니다.
- 누적 MB는 **현재 연결된 학생들**의 WebRTC 영상 수신 누계입니다. 학생이 나가면 합계에서 제외됩니다. 교사 화면을 새로고침하면 초기화됩니다.
- 이 값은 **Firebase 과금/사용량이 아니라** 교사 컴퓨터에서 수신한 WebRTC 영상 트래픽입니다.
- 데이터는 교사의 브라우저에서만 계산합니다. 별도 서버로 통계가 전송되지 않으며 DB 규칙 변경은 필요하지 않습니다.
- TURN 서버는 여전히 사용하지 않습니다.
- 코드 구문 검사와 순수 산술 테스트는 통과했지만, **실제 학교 크롬북에서의 통계 표시와 20명 동시 접속 시험은 아직 하지 않았습니다.**

### v1.3 검증 절차

1. 교사 PC와 학생 크롬북에서 새로고침하고 새 교실을 만듭니다.
2. 학생 1명 연결 후 3~6초 뒤 타일에 FPS·Mbps가 표시되는지 확인합니다.
3. 25분할 → 4분할 → 1명 확대를 바꾸면서 약 6~10초씩 관찰합니다.
4. 움직이는 화면 또는 스크롤을 이용해 차이를 확인합니다. 정지된 화면은 실제 수신 fps가 낮을 수 있습니다.
5. 가능하면 4명 → 10명 → 20명으로 늘려 합계 Mbps 및 끊김을 확인합니다.

**사전 조건:** 학생 화면을 공유하는 브라우저도 v1.2 이상(권장 v1.3)이어야 자동 프레임률 조절이 동작합니다.

## v1.4 · 고정 교실·재접속 개선 (2026-11-26)

### 중요: Firebase 보안 규칙을 업데이트해야 합니다

이번 버전은 서버에 교사의 고정 교실 코드를 저장하기 위해 Firebase Realtime Database의 `teacherRooms/{teacherUID}` 경로를 사용합니다. **GitHub에 보안 규칙 파일이 저장되는 것과 Firebase 서비스에 반영되는 것은 별개**입니다.

1. GitHub의 [database.rules.json](./database.rules.json) 원문 전체를 복사합니다.
2. Firebase 콘솔 → Realtime Database → **규칙** 탭에서 기존 전체 규칙을 교체하고 **게시**합니다.
3. 기존 `admins/{교사UID}: true` 데이터는 그대로 두세요. 새로 만들 필요가 없습니다.
4. Firebase Spark 무료 요금제를 유지합니다. 결제 계정 등록은 필요하지 않습니다.

### 교사 — 최초 1회 연결과 그 이후

- 로그인 후 저장된 고정 교실이 있으면 **같은 코드로 자동 복구**합니다.
- v1.3에서 만든 방은 `teacherRooms`에 저장되어 있지 않습니다. **처음 1회** 기존 교실 코드(예: 현재 교사 화면에 보이는 7자리 코드)를 `기존 교실 복구` 입력창에 넣어 연결하세요. 이전 코드를 모르면 `새 고정 교실 만들기`를 눌러 새 코드를 발급할 수 있습니다.
- 이후에는 **같은 교사 계정으로 다른 PC에서 로그인해도 같은 교실 코드가 복원**됩니다.
- `전체 종료`: 현재 화면 공유만 종료합니다. **교실 코드는 그대로 유지**됩니다.
- `학년도 변경 · 코드 초기화`: 확인 창을 거쳐 새 코드 발급. 이전 학생들은 새 코드를 한 번 입력해야 합니다.

### 학생 — 접속 정보 보존

- 이전 교실 코드·이름을 해당 크롬북 브라우저의 로컬 저장소에 보관하고 자동으로 표시합니다. 학생용 주소를 다시 열면 기존 정보를 확인하고 바로 **화면 공유 시작 버튼을 클릭**할 수 있습니다.
- 교실 코드가 변경되었거나 브라우저 저장소가 지워졌으면 `교실 코드 · 이름 다시 입력`을 클릭해 입력창을 열 수 있습니다.
- **Chrome 화면 공유는 보안상 사용자가 직접 선택하고 승인해야 합니다.** 교사 새로고침만으로 이미 진행 중인 학생의 공유를 자동 중단하지 않으며, 학생 자신의 브라우저를 새로고침한 경우에는 다시 승인해야 합니다.
- 교사와의 통신이 2분 이상 확인되지 않으면 개인정보 보호를 위해 학생 공유를 종료합니다.

### 연결 안정화

- 0 Mbps가 표시되어도 WebRTC 제어 채널의 ping/pong 메시지가 계속 오면 **정지 화면 가능** 상태로 표시하고 불필요한 자동 재연결을 하지 않습니다.
- ICE 연결 `failed`, 장시간 `disconnected`, 제어 응답 중단 시 교사가 새 WebRTC 연결을 자동으로 재협상합니다. 동일 학생에게 자동 복구를 최대 3회 시도하고 이후에는 타일의 `↻` 버튼으로 수동 재시도할 수 있습니다.
- 실패 복구와 교사 새로고침 시 학생이 이미 허용한 화면 캡처 트랙을 재사용하도록 설계했습니다. 브라우저 제약이나 네트워크 조건에 따라 학생의 수동 공유 재시작이 필요할 수 있습니다.
- 프레임률 자동 전환 및 실시간 진단 기능은 이전 버전과 동일합니다.
- 현재 코드는 JavaScript 구문 검사까지 진행했으며 **실제 학급 20명 동시 복구 시험은 아직 완료되지 않았습니다.**

### 권장 검증 순서

1. 수업 종료 후 Firebase 규칙부터 게시합니다.
2. **교사와 학생 크롬북 둘 다 v1.4로 새로고침**하고 다시 화면 공유를 시작합니다. 이 최초 업데이트에서는 학생마다 한 번 공유를 다시 시작해야 합니다.
3. 교사 로그인 → 기존 7자리 교실 코드 연결(처음 1번만) → 학생 1~2명 공유.
4. 교사 PC에서 `Ctrl+R`을 누르고, **기존 교실 코드가 다시 표시되며 학생 화면이 자동 재연결되는지** 확인합니다. 이때 학생들은 새로고침하거나 공유 버튼을 다시 누르지 않습니다.
5. 교사 25분할 화면에서 학생 화면을 정지 상태로 두고 0 Mbps가 나오는 경우 `연결됨 · 정지 화면 가능` 표시를 확인합니다.
6. 4명 → 10명 → 20명 순서로 확대하고 연결 끊김 및 Mbps/FPS를 측정합니다.
7. `전체 종료` 후 다시 로그인했을 때 **코드가 유지**되는지 확인합니다. 학년도 변경 버튼은 시험 전에 실제 학급에서 실행하지 마세요.
